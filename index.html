      Abans d'escriure cap línia de codi convé saber què és cada finestra de Visual Studio, què passa quan prems F5 i on van a parar els fitxers que genera.

      Què cal instal·lar

      1. Visual Studio Community, la versió gratuïta per a estudiants i ús individual. Durant la instal·lació, marca la càrrega de treball Desarrollo de escritorio de .NET (.NET desktop development).
      2. El .NET SDK, que aquesta càrrega de treball instal·la automàticament.
      3. Comprova-ho obrint un terminal i escrivint dotnet --version. Ha de respondre amb un número de versió.

      VISUAL STUDIO NO ÉS VISUAL STUDIO CODE

      Són dos productes de Microsoft amb noms gairebé iguals. Visual Studio Code és un editor lleuger; Visual Studio és un entorn complet amb el dissenyador visual de formularis, que és el que necessites per a Windows Forms.

      Visual Studio només funciona a Windows, i Windows Forms també. Si treballes amb un Mac, necessitaràs una màquina virtual amb Windows.

      Versions de .NET

      .NET publica una versió nova cada novembre. Les de número parell (8, 10…) són LTS: tenen suport durant tres anys. Les de número senar en tenen menys. Una aplicació feta amb una versió sense suport continua funcionant; simplement deixa de rebre correccions de seguretat.

      Quina triar: la que indiqui el teu curs o l'enunciat. Si no se n'indica cap, la LTS més recent.

      .NET

      La plataforma actual. Multiplataforma, rep millores cada any. Les versions es diuen simplement .NET 8, .NET 10…

      .NET Framework

      La plataforma antiga, fins a la 4.8. Només per a Windows i ja no hi arriben funcions noves. No la facis servir per a projectes nous.

      Els errors del compilador tenen sempre la mateixa estructura. Un cop la coneixes, la majoria es resolen en segons.

      Classe i objecte

      Una classe és un plànol: descriu quines dades té i què sap fer una cosa. Un objecte és cada exemplar construït a partir del plànol. Del plànol d'una aula en pots construir tantes com vulguis, i cadascuna té els seus propis valors.

      namespace AulaLabDAM;

public class Aula
{
    public string Nom { get; }
    public int Capacitat { get; set; }

    public Aula(string nom, int capacitat)
    {
        Nom = nom;
        Capacitat = capacitat;
    }
}
      var a01 = new Aula("A01", 30);
var l02 = new Aula("L02", 20);

a01.Capacitat = 32;   // només canvia a01; l02 continua tenint 20

      Per crear el fitxer de la classe: clic dret al projecte, Agregar › Clase (Add › Class). La convenció és una classe per fitxer, i el fitxer amb el mateix nom que la classe.

      La línia namespace AulaLabDAM; acabada en punt i coma és la manera curta d'escriure l'espai de noms: s'aplica a tot el fitxer i t'estalvia un nivell de claus.

      Camps i constructors

      Un camp és una variable que pertany a l'objecte. El constructor és el mètode que s'executa en fer new: té el mateix nom que la classe i no retorna res.

      public class Reserva
{
    private readonly string aula;   // readonly: només es pot assignar al constructor
    private int hores;

    public Reserva(string aula, int hores)
    {
        this.aula = aula;     // this.aula és el camp; aula sol, el paràmetre
        this.hores = hores;
    }

    // Un segon constructor que reaprofita el primer
    public Reserva(string aula) : this(aula, 1) { }
}

                throw new ArgumentOutOfRangeException(nameof(value), "La capacitat ha de ser com a mínim 1.");
            capacitat = value;
        }
    }
}

      Dins del set, value és el valor que s'està intentant assignar. Si no passa la validació, es llança una excepció i el camp no canvia.

      UN MÈTODE STATIC NO TÉ FORMULARI

      Des d'un mètode static no pots tocar controls ni camps de l'objecte: no hi ha cap objecte concret al qual pertànyer. Si ho intentes, apareix CS0120. La solució gairebé sempre és treure el static del mètode.

      Herència

      Quan escrius class Form1 : Form, la teva classe hereta tot el que sap fer Form. I Form, al seu torn, hereta d'altres classes. Per això tots els controls comparteixen propietats com Text, Location, Visible o Enabled, i esdeveniments com Click: les defineix Control, i tothom les hereta.

      public class Aula

      Esdeveniments

      Com reacciona una aplicació a l'usuari: algú avisa que ha passat una cosa, i el codi que s'hi ha subscrit respon. Fa servir: classes, mètodes i propietats.

      La idea

      En un programa de consola, el teu codi decideix l'ordre de les coses. En una aplicació de finestres, no: el programa obre la finestra i espera. Quan l'usuari fa alguna cosa (clica, escriu, tanca), el control afectat avisa, i s'executa el codi que s'hi hagi subscrit. Aquest avís és un esdeveniment.

      Respondre a un control

      Hi ha dues maneres de connectar codi a l'esdeveniment d'un control des de Visual Studio:

      1. Doble clic sobre el control al dissenyador. Crea el mètode per a l'esdeveniment més habitual d'aquell control: Click en un botó, TextChanged en una casella de text, Load en el formulari.
      2. Per a qualsevol altre esdeveniment: selecciona el control, a Propiedades clica la icona del llamp ⚡ (Events) i fes doble clic al nom de l'esdeveniment que vulguis.

      En tots dos casos, Visual Studio escriu dues coses en dos fitxers diferents:

      // El mètode: aquí escrius què ha de passar
private void btnDesa_Click(object? sender, EventArgs e)
{
    lblEstat.Text = "Reserva desada";
}
      // La subscripció: l'escriu el dissenyador, tu no la toques
this.btnDesa.Click += new System.EventHandler(this.btnDesa_Click);
      ParàmetreQuè conté
      senderEl control que ha disparat l'esdeveniment. Útil quan un mateix mètode atén diversos controls.
      eInformació addicional. En un Click, gairebé res; en un MouseClick, la posició del ratolí; en un KeyDown, la tecla premuda.

      Visual Studio pot generar el mètode amb object sender, sense interrogant. Funciona igual.

      Un mateix mètode pot atendre diversos botons: subscriu-los tots al mateix mètode des de la finestra de propietats i fes servir sender per saber quin ha estat.

      private void BotoAula_Click(object? sender, EventArgs e)
{
    if (sender is Button boto)
        lblEstat.Text = $"Has triat {boto.Text}";
}

      Què passa quan cliques

      Subscriure's des del codi

      Quan els controls es creen mentre l'aplicació s'executa, no hi ha dissenyador que et faci la subscripció: l'escrius tu amb +=. Sovint, amb una expressió lambda, un mètode sense nom escrit allà mateix.

      private void Form1_Load(object? sender, EventArgs e)
{
    string[] aules = { "A01", "A02", "L01", "L02" };

    foreach (string aula in aules)
    {
        var boto = new Button { Text = aula, Width = 80 };
        boto.Click += (s, ev) => lblEstat.Text = $"Has triat l'aula {aula}";
        flpAules.Controls.Add(boto);   // un FlowLayoutPanel els col·loca en fila
    }
}

      La lambda (s, ev) => … rep els mateixos dos paràmetres que qualsevol mètode d'esdeveniment, i a la dreta de la fletxa hi ha el que ha de fer.

      DEIXAR D'ESCOLTAR

      Amb -= et desubscrius. Però només funciona amb mètodes amb nom: una lambda no la pots tornar a referenciar. Si saps que t'hauràs de desubscriure, fes servir un mètode.

      Esdeveniments propis

      Les teves classes també poden avisar. És la manera neta que una classe de lògica informi el formulari sense saber res d'ell.

      public class GestorReserves
{
    private readonly List<string> reserves = new();

    public event EventHandler? ReservaAfegida;      // 1. es declara

    public int Total => reserves.Count;

    public void Afegeix(string reserva)
    {
        reserves.Add(reserva);
        OnReservaAfegida(EventArgs.Empty);          // 2. es dispara
    }

    protected virtual void OnReservaAfegida(EventArgs e)
        => ReservaAfegida?.Invoke(this, e);         // 3. només si algú escolta
}
      private readonly GestorReserves gestor = new();

public Form1()
{
    InitializeComponent();
    gestor.ReservaAfegida += Gestor_ReservaAfegida;
}

private void Gestor_ReservaAfegida(object? sender, EventArgs e)
{
    lblTotal.Text = $"Reserves: {gestor.Total}";
}
      1. event EventHandler? porta interrogant perquè val null mentre ningú s'hi hagi subscrit.
      2. El mètode OnReservaAfegida és una convenció de .NET: un mètode protegit amb el nom de l'esdeveniment precedit d'On, que és l'únic que el dispara.
      3. ?.Invoke dispara l'esdeveniment només si hi ha algú escoltant. Sense l'interrogant, si ningú s'hi ha subscrit, el programa peta amb NullReferenceException.

      Enviar dades amb l'esdeveniment

      Si el subscriptor necessita saber alguna cosa més, crea una classe que hereti d'EventArgs i fes servir EventHandler<T>:

      public class ReservaEventArgs : EventArgs
{
    public ReservaEventArgs(string aula) => Aula = aula;
    public string Aula { get; }
}

// A GestorReserves:
public event EventHandler<ReservaEventArgs>? ReservaAfegida;

    => ReservaAfegida?.Invoke(this, e);

// I en disparar-lo:
OnReservaAfegida(new ReservaEventArgs("A01"));

      El subscriptor rep aquesta classe com a e, i hi pot llegir e.Aula.

      QUAN NO VA COM HAURIA
      El codi s'executa dues vegades
      T'has subscrit dues vegades: des del dissenyador i també amb += al codi, o amb un += dins d'un mètode que es crida més d'un cop. Cada subscripció és una execució més.
      He esborrat o reanomenat un mètode i ara res no compila
      El dissenyador encara hi té la subscripció a Form1.Designer.cs i dona CS1061. Per reanomenar mètodes, fes-ho sempre amb F2 damunt del nom: Visual Studio actualitza també el dissenyador.
      L'esdeveniment no fa res
      Probablement no s'hi ha subscrit ningú. Posa un punt d'interrupció dins del mètode: si el programa no s'hi atura, el mètode no està connectat.

      IDEES QUE CAL ENDUR-SE

      1. Una aplicació de finestres espera; els esdeveniments són els que fan que el teu codi s'executi.
      2. El dissenyador escriu el mètode a Form1.cs i la subscripció a Designer.cs.
      3. += subscriu, -= desubscriu; cada += de més és una execució de més.
      4. Per disparar un esdeveniment propi, sempre amb ?.Invoke.
      5. Reanomena amb F2, mai a mà.

      Fitxers i excepcions

      Guardar dades perquè sobrevisquin quan tanques l'aplicació, i què fer quan alguna cosa surt malament. Fa servir: col·leccions i classes.

      On és el fitxer

      El problema número u amb fitxers no és de codi: és buscar el fitxer on no és. Quan prems F5, l'aplicació no s'executa des de la carpeta del projecte sinó des de la de sortida, dins de bin. I és allà on busca els fitxers.

      1. A l'Explorador de soluciones, selecciona el fitxer de dades.
      2. A Propiedades, busca Copiar en el directorio de salida (Copy to Output Directory).
      3. Tria Copiar si es posterior (Copy if newer).
      string ruta = Path.Combine(AppContext.BaseDirectory, "dades", "aules.txt");

      Path.Combine ajunta els trossos amb el separador correcte. AppContext.BaseDirectory és la carpeta on s'està executant l'aplicació, sigui on sigui.

      RUTES ESCRITES A MÀ

      Una ruta com C:\Users\Marta\Desktop\aules.txt funciona al teu ordinador i a cap altre. Construeix sempre les rutes a partir d'AppContext.BaseDirectory.

      Llegir i escriure text

      File.ReadAllText(ruta)Llegeix el fitxer sencer en un sol string.
      File.WriteAllLines(ruta, linies)Escriu les línies. Si el fitxer existia, el substitueix.
      File.AppendAllText(ruta, text)Afegeix text al final, sense esborrar el que hi havia.

      private List<Aula> CarregaAules(string ruta)
{
    var aules = new List<Aula>();
    if (!File.Exists(ruta))
        return aules;

    string[] linies = File.ReadAllLines(ruta);
    for (int i = 1; i < linies.Length; i++)      // la 0 és la capçalera
    {
        string[] camps = linies[i].Split(';');
        if (camps.Length < 2)
            continue;                              // línia buida o mal formada

        if (int.TryParse(camps[1], out int capacitat))
            aules.Add(new Aula(camps[0], capacitat));
    }
    return aules;
}

private void DesaAules(string ruta, List<Aula> aules)
{
    var linies = new List<string> { "Nom;Capacitat" };
    foreach (var a in aules)
        linies.Add($"{a.Nom};{a.Capacitat}");

    File.WriteAllLines(ruta, linies);
}

      Convertir text en números

      int.Parse("abc") llança FormatException. Amb dades que vénen de l'usuari o d'un fitxer, fes servir TryParse, que retorna false en lloc de petar.

      Amb els decimals hi ha un parany més subtil. En un Windows en català o en castellà, el separador decimal és la coma. Si un fitxer té els números amb punt, la conversió no falla: dona un resultat erroni sense avisar.

      ✕ Error silenciós
      double h = double.Parse("7.5");
// en un Windows en català: 75
      ✓ Correcte
      using System.Globalization;

double h = double.Parse("7.5",
    CultureInfo.InvariantCulture);  // 7.5

      La regla: per a fitxers i per a dades que es passen entre programes, CultureInfo.InvariantCulture, que sempre fa servir el punt. Per mostrar números a l'usuari, la cultura del sistema, que és la que fan servir per defecte. I en escriure el fitxer, igual: h.ToString(CultureInfo.InvariantCulture).

      Excepcions: try i catch

      Una excepció és un error que es produeix mentre el programa s'executa. Si ningú la captura, l'aplicació es tanca. Amb try i catch la captures i decideixes què fer.

      private void btnCarrega_Click(object? sender, EventArgs e)
{
    btnCarrega.Enabled = false;
    try
    {
        var aules = CarregaAules(ruta);
        lstAules.DataSource = aules;
    }
    catch (FileNotFoundException)
    {
        MessageBox.Show("No s'ha trobat el fitxer d'aules.", "Error",
            MessageBoxButtons.OK, MessageBoxIcon.Error);
    }
    catch (IOException ex)
    {
        MessageBox.Show($"No s'ha pogut llegir el fitxer: {ex.Message}");
    }
    finally
    {
        btnCarrega.Enabled = true;     // passi el que passi
    }
}

      Els catch es comproven en ordre i s'executa el primer que encaixa. Per això van del més concret al més general: FileNotFoundException és un cas particular d'IOException, i si els poses al revés, el compilador et dona CS0160.

      ExcepcióQuan apareix
      FileNotFoundExceptionEl fitxer no existeix.
      DirectoryNotFoundExceptionAlguna carpeta de la ruta no existeix.
      IOExceptionQualsevol problema d'entrada i sortida, com un fitxer obert per un altre programa.
      FormatExceptionUn text no té el format esperat, com int.Parse("abc").
      NullReferenceExceptionS'ha intentat fer servir una variable que val null.
      ArgumentOutOfRangeExceptionUn valor fora del rang permès, o una posició que no existeix en una llista.
      InvalidOperationExceptionL'operació no té sentit en l'estat actual de l'objecte.

      NO T'EMPASSIS LES EXCEPCIONS

      Un catch { } buit fa desaparèixer l'error sense deixar rastre: el programa continua com si res, amb dades incorrectes, i mai sabràs per què. Si captures una excepció, fes-hi alguna cosa: avisa l'usuari, o com a mínim escriu-la amb Debug.WriteLine.

      I el missatge per a l'usuari, que digui què ha passat i què pot fer. «No s'ha trobat el fitxer d'aules» és útil; «Error 0x80070002», no.

      Llançar excepcions

      Les teves classes també poden llançar excepcions quan reben dades que no tenen sentit. Així el problema s'atura on es produeix, i el formulari decideix com explicar-lo a l'usuari.

      public void Afegeix(Reserva r)

    if (r.Hores < 1 || r.Hores > 8)
        throw new ArgumentOutOfRangeException(nameof(r), "Una reserva ha de durar entre 1 i 8 hores.");

    reserves.Add(r);

      nameof(r) escriu el nom del paràmetre com a text. Si algun dia el reanomenes, el missatge es manté correcte.

      using i fitxers oberts

      Quan obres un fitxer amb StreamReader o StreamWriter, el sistema el deixa bloquejat fins que el tanques. Amb using, es tanca sol en sortir del bloc, fins i tot si hi ha hagut una excepció:

      using var lector = new StreamReader(ruta);

      Interfícies i LINQ

      Programar contra un contracte en lloc d'una classe concreta, i consultar col·leccions sense escriure bucles a mà. Fa servir: classes, col·leccions i lambdes.

      Què és una interfície

      Una interfície és un contracte: una llista de mètodes que una classe es compromet a tenir, sense dir com els fa. Qui fa servir la interfície no necessita saber quina classe hi ha darrere.

      public interface IExportador
{
    void Exporta(IReadOnlyList<Reserva> reserves, string ruta);
}

public class ExportadorCsv : IExportador
{
    public void Exporta(IReadOnlyList<Reserva> reserves, string ruta)
    {
        var linies = new List<string> { "Aula;Data;Hores" };
        foreach (var r in reserves)
            linies.Add($"{r.Aula};{r.Data:yyyy-MM-dd};{r.Hores}");
        File.WriteAllLines(ruta, linies);
    }
}
      // El formulari no sap quin exportador té; només que en té un
private IExportador exportador = new ExportadorCsv();

private void btnExporta_Click(object? sender, EventArgs e)
{
    exportador.Exporta(gestor.Reserves, rutaSortida);
}

      JA N'HAS FET SERVIR SENSE SABER-HO

      foreach funciona amb qualsevol cosa que implementi IEnumerable<T>; using, amb qualsevol cosa que implementi IDisposable. I moltes biblioteques funcionen així: per generar un PDF, QuestPDF et demana una classe que implementi la seva interfície IDocument.

      LINQ: la idea

      LINQ és una manera de fer preguntes a una col·lecció encadenant operacions. Cada operació rep una col·lecció i en retorna una altra, i la següent treballa sobre el resultat de l'anterior.

      public class Reserva
{
    public string Aula { get; set; } = "";
    public DateTime Data { get; set; }
    public int Hores { get; set; }
    public string Professor { get; set; } = "";
}
      List<string> professors = reserves
    .Where(r => r.Aula == "A01")       // només les de l'aula A01
    .OrderBy(r => r.Data)              // per data
    .Select(r => r.Professor)          // ens quedem només amb el nom
    .ToList();                         // ho convertim en una llista

      Les operacions bàsiques

      OperacióQuè fa

      Select(transformació)Transforma cada element en una altra cosa.
      OrderBy / OrderByDescendingOrdena, ascendent o descendent.
      ThenBySegon criteri d'ordenació, per als empats.
      Count, Sum, Average, Min, MaxCalculen un sol valor a partir de tots.
      Any(condició) / All(condició)N'hi ha algun que la compleixi? La compleixen tots?
      FirstOrDefault(condició)El primer que la compleix, o null si no n'hi ha cap.
      ToList()Executa la consulta i guarda el resultat en una llista.

      Agrupar

      GroupBy reparteix els elements en grups segons un criteri. Cada grup té una Key, que és el valor que comparteixen, i es pot recórrer com qualsevol col·lecció.

      using System.Diagnostics;

foreach (var grup in reserves.GroupBy(r => r.Aula))
{
    int hores = grup.Sum(r => r.Hores);
    Debug.WriteLine($"{grup.Key}: {grup.Count()} reserves, {hores} h");
}

      using System.Globalization;

foreach (var perAula in reserves.GroupBy(r => r.Aula))
{
    foreach (var perSetmana in perAula.GroupBy(r => ISOWeek.GetWeekOfYear(r.Data)))
    {
        // perAula.Key: l'aula · perSetmana.Key: el número de setmana
        int hores = perSetmana.Sum(r => r.Hores);

      Dos paranys de LINQ

      La consulta s'executa tard

      Una consulta LINQ no s'executa quan l'escrius, sinó quan la recorres. Si entremig la llista original canvia, el resultat també. Quan vulguis una foto fixa del resultat, acaba la consulta amb .ToList().

      First, Average i Max peten amb una llista buida

      First() sobre una col·lecció buida llança InvalidOperationException. Fes servir FirstOrDefault() i comprova si el resultat és null. Average, Min i Max fan el mateix: abans de calcular-los, comprova que hi ha elements amb Any().

      IDEES QUE CAL ENDUR-SE

      1. Una interfície diu què s'ha de fer; cada classe que la implementa decideix com.
      2. Programar contra una interfície permet canviar la implementació tocant una sola línia.
      3. LINQ encadena operacions: Where filtra, OrderBy ordena, Select transforma.
      4. GroupBy dona grups amb una Key; dins de cada grup pots tornar a fer Sum, Count o un altre GroupBy.
      5. FirstOrDefault en lloc de First, i Any() abans d'Average.

      Fils, paquets i veu

      Què passa quan el codi no s'executa on creus, com afegir biblioteques externes, i els paranys de les biblioteques de veu de Windows. Fa servir: esdeveniments i excepcions.

      El fil de la interfície

      Una aplicació de finestres té un fil d'execució principal, el fil de la interfície: dibuixa la finestra i atén l'usuari. Tots els controls pertanyen a aquest fil, i només aquest fil els pot tocar.

      Però hi ha codi que s'executa en altres fils: un temporitzador de tipus System.Timers.Timer, una tasca llançada amb Task.Run, o una biblioteca que t'avisa quan ha acabat alguna cosa, com un reconeixedor de veu. Si des d'un d'aquests fils toques un control, el programa peta.

      L'ERROR QUE ARA SURT I ARA NO

      Amb el depurador connectat (F5), tocar un control des d'un altre fil llança InvalidOperationException. Sense depurador pot semblar que funciona, i fallar de manera aleatòria més endavant. Si et passa alguna cosa estranya i intermitent amb la interfície, sospita d'això.

      Invoke

      La solució és demanar al fil de la interfície que faci la feina per tu. Aquest patró val per a qualsevol mètode que actualitzi la pantalla i que es pugui cridar des d'un altre fil:

      private void ActualitzaEstat(string text)
{
    if (InvokeRequired)                       // som en un altre fil?
    {
        Invoke(new Action(() => ActualitzaEstat(text)));   // demana-ho al fil de la interfície
        return;
    }
    lblEstat.Text = text;                     // aquí ja som al fil correcte
}

      Si fas servir sempre ActualitzaEstat en lloc de tocar lblEstat directament, ja no t'has de preocupar de quin fil t'està cridant.

      TemporitzadorOn s'executaCal Invoke?
      System.Windows.Forms.TimerEl seu Tick, al fil de la interfície. És el del quadre d'eines.No
      System.Timers.TimerEl seu Elapsed, en un altre fil.Sí

      No bloquejar la finestra

      Si un mètode d'esdeveniment fa una feina llarga, la finestra es congela: no es redibuixa, no respon als clics, i Windows hi afegeix «No responde» al títol. La solució és fer la feina en un altre fil amb Task.Run i esperar-la amb await:

      private async void btnCarrega_Click(object? sender, EventArgs e)
{
    btnCarrega.Enabled = false;
    lblEstat.Text = "Carregant…";

    var dades = await Task.Run(() => CarregaDadesLentes());   // en un altre fil

    lblEstat.Text = $"{dades.Count} registres";   // de tornada al fil de la interfície
    btnCarrega.Enabled = true;
}

      Mentre CarregaDadesLentes treballa, la finestra continua responent. I després de l'await tornes a ser al fil de la interfície, de manera que pots tocar controls sense Invoke.

      async void només s'ha de fer servir en mètodes d'esdeveniment, com aquest. En la resta de mètodes asíncrons, async Task.

      1 · EL RECONEIXEDOR TÉ IDIOMA

      Windows només reconeix la veu en els idiomes que té instal·lats, i en català no n'hi ha. Crear el reconeixedor sense paràmetres, new SpeechRecognitionEngine(), fa servir l'idioma del sistema i pot fallar en arrencar. Llista els disponibles i tria'n un explícitament:

      using System.Speech.Recognition;

// Camp del formulari: el reconeixedor ha de viure tant com la finestra
private SpeechRecognitionEngine? reconeixedor;

// Dins del mètode que posa en marxa la veu:
var disponibles = SpeechRecognitionEngine.InstalledRecognizers();
var info = disponibles.FirstOrDefault(r => r.Culture.Name == "es-ES")
           ?? disponibles.FirstOrDefault();

if (info is null)
{
    MessageBox.Show("No hi ha cap reconeixedor de veu instal·lat en aquest equip.");
    return;
}

reconeixedor = new SpeechRecognitionEngine(info);

      Desa'l en un camp del formulari i no en una variable local del mètode: una variable local desapareix quan el mètode acaba, i amb ella el reconeixedor.

      2 · LA GRAMÀTICA HA DE PARLAR EL MATEIX IDIOMA

      Les paraules que vols reconèixer han de ser de l'idioma del reconeixedor: un reconeixedor en castellà reconeixerà malament una paraula catalana. I la gramàtica ha de declarar la mateixa cultura, o en carregar-la tindràs una excepció que diu que l'idioma no coincideix.

      var ordres = new Choices("nueva reserva", "cancelar", "ayuda");
var gb = new GrammarBuilder(ordres) { Culture = info.Culture };   // mateix idioma

reconeixedor.LoadGrammar(new Grammar(gb));
reconeixedor.SpeechRecognized += Reconeixedor_SpeechRecognized;
reconeixedor.SetInputToDefaultAudioDevice();
reconeixedor.RecognizeAsync(RecognizeMode.Multiple);   // escolta contínua

      3 · L'AVÍS ARRIBA DES D'UN ALTRE FIL

      L'esdeveniment SpeechRecognized pot arribar des d'un fil que no és el de la interfície. Actualitza la pantalla sempre a través d'un mètode amb el patró d'Invoke. I un consell: el resultat porta un grau de confiança entre 0 i 1, i val la pena ignorar els reconeixements dubtosos.

        return;                                   // massa dubtós: no fem res

    string resposta = gestor.Processa(e.Result.Text);
    ActualitzaEstat(resposta);                    // ja fa servir Invoke per dins
}

      IDEES QUE CAL ENDUR-SE

      1. Només el fil de la interfície pot tocar els controls; des d'un altre, Invoke.
      2. Una feina llarga, amb await Task.Run(…), perquè la finestra no es congeli.

      Proves unitàries

      Comprovar automàticament que la teva lògica fa el que ha de fer, sense obrir la finestra ni clicar res. Fa servir: classes i excepcions.

      Què és una prova unitària

      Una prova unitària és un mètode que crida el teu codi amb unes dades concretes i comprova que el resultat és el que esperes. Visual Studio les pot executar totes de cop i dir-te quines fallen. Cada prova segueix tres passos:

      Les proves són per a la lògica: classes com Aula, GestorReserves o GestorOrdres. El formulari no es prova així. Per això convé que la lògica no visqui dins del formulari, sinó en classes pròpies.

      Crear el projecte de proves

      1. Clic dret a la solució (no al projecte), Agregar › Nuevo proyecto (Add › New Project).
      2. Tria Proyecto de prueba de xUnit (xUnit Test Project) i anomena'l com l'aplicació acabat en .Tests.
      3. Al projecte de proves, clic dret a Dependencias, Agregar referencia de proyecto (Add Project Reference), i marca el projecte de l'aplicació.
      4. Obre el .csproj del projecte de proves i canvia el TargetFramework perquè acabi igual que el de l'aplicació, en -windows.
      <TargetFramework>net8.0-windows</TargetFramework>

      Escriure proves

      using AulaLabDAM;

public class AulaTests
{
    [Fact]
    public void Capacitat_ValorValid_EsGuarda()
    {
        // Prepara
        var aula = new Aula("A01", 30);

        // Actua
        aula.Capacitat = 25;

        // Comprova
        Assert.Equal(25, aula.Capacitat);
    }

    [Theory]
    [InlineData(0)]
    [InlineData(-5)]
    public void Capacitat_ValorInvalid_LlancaExcepcio(int valor)
    {
        var aula = new Aula("A01", 30);

        Assert.Throws<ArgumentOutOfRangeException>(() => { aula.Capacitat = valor; });
    }
}
      ElementQuè fa
      [Fact]Marca un mètode com a prova.
      [Theory] + [InlineData]La mateixa prova, executada un cop per a cada joc de dades.
      Assert.Equal(esperat, real)Comprova que són iguals. L'ordre importa: si falla, el missatge diu quin esperaves i quin has obtingut.
      Assert.True(condició)Comprova que és certa.
      Assert.Throws<T>(acció)Comprova que l'acció llança aquella excepció.

      El nom de la prova ha de dir què prova: què, en quina situació i què ha de passar. Quan una falli, el nom ja t'explicarà què s'ha trencat.

      Executar-les

      Menú Prueba › Explorador de pruebas (Test › Test Explorer) i Ejecutar todas las pruebas. O des d'un terminal a la carpeta de la solució: dotnet test.

      Què val la pena provar

      • Els valors límit. Si la capacitat ha de ser d'1 a 200, prova 0, 1, 200 i 201. Els errors s'amaguen a les vores.
      • Els valors invàlids. Text buit, números negatius, una data passada. Han de ser rebutjats.
      • Els casos buits. Una llista sense elements, un fitxer sense línies. És on peten First i Average.
      • L'estat després d'una acció. Després d'afegir una reserva, el total ha augmentat en una?

      No cal provar-ho tot. Prova el que és fàcil d'equivocar i el que seria greu que fallés.

      IDEES QUE CAL ENDUR-SE

      1. Prepara, actua, comprova: una prova, una sola cosa.
      2. Es prova la lògica, no el formulari: posa-la en classes pròpies i public.
      3. El projecte de proves ha d'acabar en -windows, com l'aplicació.
      4. Assert.Equal amb l'esperat primer.
      5. Els errors viuen als límits i als casos buits.

      MÈTODE GENERAL

      • Fes-hi doble clic per anar a la línia.
      • Busca el codi en aquesta secció o a internet.

      Errors de compilació

      Impedeixen que el programa es construeixi. Apareixen a la Lista de errores amb una creu vermella i un codi que comença per CS.

      CS0103El nom no existeix en el context actual

      Fas servir una variable o un control que el compilador no coneix en aquell punt: s'ha declarat dins d'un altre bloc, està mal escrit, o és un control que has reanomenat.

      Solució: revisa majúscules i minúscules. Si és un control, comprova el seu (Name) a Propiedades.

      CS0246No es troba el tipus o l'espai de noms

      Hi falta un using al principi del fitxer, o el paquet NuGet que el conté.

      Solució: cursor damunt del nom i Ctrl+.. Si no proposa cap using, és que falta instal·lar el paquet.

      CS1061El tipus no conté cap definició per a aquest membre

      Crides un mètode o una propietat que no existeix. El cas més freqüent: has esborrat o reanomenat a mà un mètode d'esdeveniment, i Form1.Designer.cs encara el crida.

      Solució: doble clic a l'error per obrir el Designer.cs i esborra només la línia amb += que apunta al mètode desaparegut. O torna a crear el mètode amb el mateix nom.

      CS1002S'esperava ;

      Falta un punt i coma. Sovint l'error s'assenyala a la línia següent de la que realment el té.

      CS1513S'esperava }

      Les claus no estan aparellades: n'has obert més de les que has tancat.

      Solució: Ctrl+K, Ctrl+D formata el document; el sagnat mal posat et mostrarà on falta la clau.

      CS0029No es pot convertir implícitament un tipus en un altre

      Assignes un valor d'un tipus a una variable d'un altre. Típic: guardar el Text d'una casella en un int.

      Solució: de text a número, int.TryParse; de número a text, .ToString() o interpolació.

      CS0266Existeix una conversió explícita; potser falta un cast

      La conversió és possible, però hi pots perdre informació. Per exemple, de double a int es perden els decimals.

      Solució: si és el que vols, (int)valor; si vols arrodonir, (int)Math.Round(valor).

      CS0664Un literal double no es pot convertir a decimal

      Has escrit decimal preu = 19.99;.

      Solució: afegeix una m al número: 19.99m.

      CS0120Cal una referència a un objecte

      Des d'un mètode static intentes fer servir un camp, un control o un mètode que pertanyen a un objecte.

      Solució: gairebé sempre, treure el static del mètode.

      CS0161No tots els camins de codi retornen un valor

      El mètode ha de retornar alguna cosa, però hi ha algun camí (un if sense else, per exemple) que arriba al final sense return.

      CS0165Ús d'una variable local no assignada

      Fas servir una variable abans de donar-li cap valor. Solució: inicialitza-la en declarar-la.

      CS0122No és accessible pel seu nivell de protecció

      El membre és private o internal i l'intentes fer servir des de fora. Solució: exposa'l amb una propietat pública, o canvia el modificador si té sentit.

      CS0535La classe no implementa un membre de la interfície

      Falta algun dels mètodes que la interfície exigeix. Solució: cursor damunt del nom de la interfície i Ctrl+., Implementar interfaz.

      CS1503No es pot convertir l'argument

      Passes a un mètode un valor d'un tipus diferent del que espera. Revisa l'ordre i el tipus dels paràmetres.

      CS0160Un catch anterior ja captura aquesta excepció

      Has posat un catch general abans d'un de més concret. Solució: del més concret al més general.

      CS8618 · avísUna propietat no anul·lable no té valor en sortir del constructor

      Una propietat de tipus string (sense interrogant) pot quedar a null. Solució: dona-li valor inicial, = "";, assigna-la al constructor, o declara-la string? si realment pot no tenir valor.

      CS8602 · avísPossible desreferència d'una referència null

      Fas servir una variable que podria valer null. Si ho val, tindràs un NullReferenceException. Solució: comprova-la abans amb is not null, o fes servir ?. i ??.

      Errors en execució

      El programa compila, però peta mentre s'executa. Visual Studio s'atura a la línia del problema i mostra el tipus d'excepció.

      NullReferenceExceptionObject reference not set to an instance of an object

      Una variable val null i n'intentes fer servir alguna cosa. Causes típiques: una variable que no s'ha inicialitzat, un Find o FirstOrDefault que no ha trobat res, o un esdeveniment disparat sense ?..

      Solució: a la línia aturada, passa el ratolí per sobre de cada variable i mira quina val null.

      InvalidOperationExceptionCross-thread operation not valid

      Has tocat un control des d'un fil que no és el de la interfície: un temporitzador, una tasca o un reconeixedor de veu. Solució: el patró d'Invoke.

      InvalidOperationExceptionCollection was modified

      Has afegit o tret elements d'una llista mentre la recorries amb foreach. Solució: RemoveAll, o recorre una còpia amb .ToList().

      InvalidOperationExceptionSequence contains no elements

      First(), Average(), Max() o Min() sobre una col·lecció buida. Solució: FirstOrDefault(), o comprova abans amb Any().

      FormatExceptionEl text no té el format esperat

      int.Parse o double.Parse amb un text que no és un número. Solució: TryParse. Si són decimals d'un fitxer, CultureInfo.InvariantCulture.

      ArgumentOutOfRangeExceptionValor o posició fora de rang

      Has demanat una posició que no existeix en una llista (llista[5] quan en té tres), o una validació ha rebutjat un valor. Recorda que les posicions comencen per 0: l'última és Count - 1.

      IndexOutOfRangeExceptionL'índex és fora dels límits de l'array

      El mateix amb arrays. El cas clàssic: camps[1] després d'un Split sobre una línia buida o sense separador. Solució: comprova camps.Length abans.

      KeyNotFoundExceptionLa clau no és al diccionari

      Solució: TryGetValue o ContainsKey abans de llegir.

      FileNotFoundExceptionNo es troba el fitxer

      Gairebé sempre, el fitxer és a la carpeta del projecte però no a la de sortida. Solució: Copiar en el directorio de salida i rutes amb AppContext.BaseDirectory.

      IOExceptionEl fitxer l'està fent servir un altre procés

      El fitxer és obert per un altre programa, o pel teu mateix codi sense tancar-lo. Passa molt amb CSV oberts a Excel. Solució: tanca'l, i obre els Stream sempre amb using.

      Problemes de l'entorn

      No són errors del teu codi, però t'aturen igual.

      Pregunta si vols executar l'última compilació correcta

      El codi actual té errors. Si respons que sí, executaràs una versió antiga i provaràs canvis que no hi són. Respon que no i corregeix els errors.

      MSB3027 · MSB3021No es pot copiar l'executable perquè està en ús

      L'aplicació encara està oberta, potser minimitzada o aturada al depurador, i bloqueja l'executable. Solució: tanca-la, o atura la depuració amb Mayús+F5, i torna a compilar.

      El dissenyador s'obre en blanc o mostra una pàgina d'error

      En blanc: memòria cau de Visual Studio, esborra-la. Pàgina d'error: gairebé sempre és un error de compilació, sovint un CS1061 al Designer.cs.

      El component propi no surt al quadre d'eines

      Només hi apareix quan el projecte compila sense errors. Compila i revisa la llista d'errors.

      NU1201El projecte no és compatible

      El projecte de proves és net8.0 i fa referència a una aplicació net8.0-windows. Solució: canvia el TargetFramework del projecte de proves perquè acabi en -windows. Vegeu secció 9.

      El projecte s'ha creat amb .NET Framework

      El .csproj diu v4.8 o similar. Les biblioteques actuals no s'hi instal·laran. Solució: crea un projecte nou amb la plantilla correcta i copia-hi el codi. Vegeu secció 1.

      En obrir el projecte en un altre equip, falten els paquets

      Normalment es descarreguen sols en compilar. Si no, clic dret a la solució, Restaurar paquetes NuGet, o dotnet restore al terminal.

      Ventana › Restablecer diseño de la ventana (Window › Reset Window Layout).
